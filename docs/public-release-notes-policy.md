# 公开版更新说明边界

官网更新历史、Sparkle 更新说明和两个官网镜像使用同一套公开文案。它们服务于用户，不承担工程日志、测试报告或内部复盘的职责。

## 写什么

- 当前版本保留版本号、发布日期和一句简短说明
- 历史版本只保留版本号和发布日期
- 需要用户立即采取动作时，使用独立通知或帮助页面，不把处置细节长期堆在更新历史中

## 不写什么

- 自动化测试数量、构建过程和发布流水线
- 未公开版本如何合并、内部排期和临时版本号
- 竞态、线程、缓存、框架、API 等实现细节
- 调试过程、根因推演、竞品痕迹和内部人员信息
- 为显得丰富而拆开的细碎修复；可以收束为「其他细节优化」

## 需要另行处理的内容

安全、隐私、破坏性变化或必要用户动作通过独立通知、帮助页面或应用内提示处理。公开更新历史不承担长期告警职责；完整影响、处置和验证证据保留在内部 release evidence。

## 发布前检查

1. 当前版本在官网更新历史与对应的 `notes/Chock-<version>.html` 使用同一句简短说明。
2. 主站与大陆站使用同一份静态文件，不单独改文案。
3. 自动测试检查公开页面没有测试数量、内部根因或未发布版本说明。
4. 涉及隐私、安全、兼容性和必要用户动作时，确认已有合适的独立沟通入口。

完整测试证据、根因和发布过程继续保存在产品内部文档，不复制到公开页面。
